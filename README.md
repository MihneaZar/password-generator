## Description
Console application for generating website/app passwords based on a saved password (only the hash is saved).

## Requirements
- The [inputimeout](https://pypi.org/project/inputimeout/) library for reading from console with a timeout;
- The [PWInput](https://pypi.org/project/pwinput/) library for inputting hidden password;
- The [termcolor](https://pypi.org/project/termcolor/) library for colored console text;
- The [cursor](https://pypi.org/project/cursor/) library for hiding the cursor in console.

## How it functions
On first-time use, it prompts the user to create a password that is at least moderately-strong, based on a few semi-arbitrary rules. <br>
It only saves the SHA-256 hash, so this password is only breakable through brute-force algorithms. <br>
The user then has to input the password on every use, after which there is a limited time to input the name of the website/app before a timeout occurs. <br>
The passwords are generated by combining the program's password with the name of website/app, generating a SHA-256 hash from it, then using the hash values to generate a 32-character pseudo-random password. <br>

## Possible Naming Conventions
Naturally, in order to generate the same website/app password every time, the naming convention must remain the same. <br>
Some examples of naming conventions are:
- using the website domain name, or the app's name (e.g. https://example.com -> example);
- for websites where the user has multiple accounts, it could be account_name@website_name or account_name:website_name;
- for email accounts, it could be username@email_provider.com or username@email_provider;
- etc.

Which conventions are used isn't the important part, the important part is that they remain the same. <br>
Writing them down somewhere could be useful (remember: the program's password is essential not to be shared, but also not to be forgotten!).

## Extra Info
The only issue encountered so far is that certain websites have password length limits. <br>
For example, https://www.formula1.com/ has a limit of 30 characters - therefore, the two characters at the beginning or at the end need to be cut off. <br>
Once again, it does not matter how the passwords are modified to fit specific requirements, what matters is to always apply the same convention. <br>
Tested only on Windows 11.
